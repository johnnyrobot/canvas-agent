Who should own the accessibility review screen’s state?

In the app today, the accessibility review screen keeps one piece of memory — which finding you have selected — in a loose variable that sits outside the screen itself, alongside 56 other fields belonging to thirteen other screens. Nothing resets it, and no test can reach it. ADR-0002 proposes moving that memory inside a screen model that owns both the state and the rules for changing it.

This page is that screen model, with the screen removed. Press the buttons, watch the state. The question to answer: does a model that owns its own memory behave the way you’d expect an instructor to experience this screen? Use the walkthroughs — especially “Selection goes stale” — and switch the comparison toggle to feel the difference against today.
